Python 元编程 📅 2024-01-15

黑魔法：利用 AST 与元编程实现运行时代码注入

在 Python 的世界里，装饰器和元类已经能帮我们完成大部分的动态代理工作。但如果你想在不修改目标函数源码、不包裹装饰器的前提下，动态地在函数体中间插入一段监控逻辑，该怎么做？答案是：直接操作 AST（抽象语法树） 并重构字节码。

1. 什么是 AST？

Python 解释器在执行代码时，会先将源码解析为抽象语法树（Abstract Syntax Tree）。通过 Python 内置的 ast 模块，我们可以在代码运行期拦截并修改这个树状结构，然后再将其编译回字节码执行。

2. 核心实现：AST 节点转换器

我们可以继承 ast.NodeTransformer，在遍历语法树时，动态寻找特定的函数定义，并在其头部或尾部插入我们自定义的 AST 节点：

import ast
import inspect

class CodeInjector(ast.NodeTransformer):
    def visit_FunctionDef(self, node):
        # 寻找目标函数
        if node.name == "target_function":
            # 构造一个 print("Injected successfully! ✨") 的 AST 节点
            log_node = ast.Expr(
                value=ast.Call(
                    func=ast.Name(id="print", ctx=ast.Load()),
                    args=[ast.Constant(value="[AST Magic] Code Injected successfully! ✨")],
                    keywords=[]
                )
            )
            # 将新节点插入到函数体最前面
            node.body.insert(0, log_node)
        return node

3. 动态编译与替换

通过 inspect.getsource 获取源码，利用 ast.parse 生成树，修改后用内置的 compile 编译，最后动态替换函数的 __code__ 属性：

def target_function():
    print("Executing original logic...")

# 1. 获取源码并解析为 AST
source = inspect.getsource(target_function)
tree = ast.parse(source)

# 2. 注入代码
transformer = CodeInjector()
modified_tree = transformer.visit(tree)
ast.fix_missing_locations(modified_tree)

# 3. 编译并替换字节码
compiled_code = compile(modified_tree, filename="<ast_magic>", mode="exec")
namespace = {}
exec(compiled_code, namespace)

# 替换原函数的字节码
target_function.__code__ = namespace["target_function"].__code__

# 测试运行
target_function()
# 输出:
# [AST Magic] Code Injected successfully! ✨
# Executing original logic...

这种技术在编写无侵入式 APM 监控、热更新补丁以及高级 AOP 框架时非常有用。当然，由于它直接修改了底层字节码，使用时需要格外小心！

异步编程 底层原理 📅 2024-01-10

手写事件循环：从零实现 Python 异步协程调度器

Python 的 async/await 让我们能轻松编写高并发程序。但 asyncio 内部究竟是如何工作的？今天我们不依赖任何第三方库，仅用 Python 原生的生成器（Generator）和 select 模块，从零手写一个单线程高并发事件循环。

1. 协程的本质：生成器

在 Python 中，协程的本质是可以被暂停和恢复执行的函数。生成器中的 yield 完美契合这一特性。我们可以把每个协程包装成一个任务（Task）：

class Task:
    def __init__(self, coro):
        self.coro = coro  # 协程对象（生成器）
        self.value = None # 协程产出的值
        
    def run(self):
        try:
            # 恢复协程执行，并传入上一次的结果
            return self.coro.send(self.value)
        except StopIteration as e:
            # 协程执行完毕
            return "FINISHED"

2. 基于 Select 的 I/O 多路复用调度器

当协程遇到 I/O 阻塞（如 socket 读写）时，我们不能让线程死等，而是要把 socket 注册到操作系统的 select/epoll 中，让出 CPU。当 socket 可读写时，再唤醒对应的协程：

import select
import socket

class EventLoop:
    def __init__(self):
        self.ready_tasks = []  # 就绪任务队列
        self.read_waiting = {} # socket -> waiting Task 的映射

    def create_task(self, coro):
        task = Task(coro)
        self.ready_tasks.append(task)
        return task

    def run_forever(self):
        while self.ready_tasks or self.read_waiting:
            # 1. 如果没有就绪任务，但有等待 I/O 的任务，进行 select 阻塞等待
            if not self.ready_tasks and self.read_waiting:
                ready_to_read, _, _ = select.select(self.read_waiting.keys(), [], [])
                for sock in ready_to_read:
                    task = self.read_waiting.pop(sock)
                    self.ready_tasks.append(task)

            # 2. 执行所有就绪任务
            if self.ready_tasks:
                task = self.ready_tasks.pop(0)
                result = task.run()
                
                if result == "FINISHED":
                    continue
                
                # 如果任务 yield 了一个 socket，说明它在等待该 socket 的可读事件
                if isinstance(result, socket.socket):
                    self.read_waiting[result] = task

通过这种方式，我们用单线程实现了非阻塞 I/O 调度。这就是 asyncio、Node.js 以及 Go 语言 runtime 调度器的核心思想。理解了它，异步编程中的各种 Race Condition 和 Deadlock 也就迎刃而解了。

内存管理 CPython 📅 2024-01-05

内存炼金术：Python 垃圾回收机制与引用计数深潜

很多人说 Python 有垃圾回收（GC），所以不需要关心内存。但在处理海量数据或高频长连接服务时，不合理的内存占用会导致 OOM（内存溢出）。本文带你深潜 CPython 源码，剖析 Python 内存管理的底层逻辑。

1. 第一道防线：引用计数（Reference Counting）

Python 中万物皆对象，每个对象头部都有一个 ob_refcnt 字段。当引用增加时加 1，引用减少时减 1。一旦降为 0，内存立即释放。这种机制实时性极高，但它有一个致命缺陷：循环引用。

# 循环引用示例：a 和 b 互相引用，即使 del 之后，它们的引用计数依然为 1，导致内存泄漏
a = []
b = []
a.append(b)
b.append(a)
del a
del b

2. 第二道防线：分代回收（Generational GC）

为了解决循环引用，CPython 引入了标记-清除（Mark and Sweep）算法，并将其划分为三代（0代、1代、2代）。新创建的对象在第0代，经历过 GC 存活下来的对象会晋升到下一代。代数越高，GC 扫描的频率越低。

3. 避免内存泄漏的黄金法则

  • 善用 weakref（弱引用）：弱引用不会增加对象的引用计数，是解决缓存和观察者模式中循环引用的利器。
  • 手动控制 GC 阀值：在内存敏感的密集计算任务中，可以通过 gc.disable() 暂时关闭自动回收，并在合适时机手动调用 gc.collect()。
  • 使用 __slots__ 瘦身对象：默认情况下，Python 实例使用字典 __dict__ 存储属性。声明 __slots__ 可以阻止动态字典的创建，在需要实例化数百万个小对象时，能节省 70% 以上的内存！
